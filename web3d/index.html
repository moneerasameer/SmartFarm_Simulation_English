        Data pipeline
        
        
          
          
        1. Sensor nodes — synthetic soil/temperature/humidity frames from the recorded dataset (or live serial/MQTT frames).
          2. 
          
        2. ESP32 + LoRa — frame is encoded, airtime is computed with the Semtech CSS formula.
          3. 
          
        3. Gateway — forwards the frame to the local server; losses are taken from the dataset.
          4. 
          
        4. Server & storage — frames are kept in memory for the session (no database server required).
          5. 
          
        5. Dashboard — charts, alerts and the 3D twin read the same processed frame.
          6. 
        
        

        
        Honesty notes
        
        
          
          
        • No physical sensor, pump or LoRa radio is connected in the default mode.
          • 
          
        • RSSI/SNR are model outputs, not measurements.
          • 
          
        • Packet losses are the recorded dataset outcomes; they are not produced by this page.
          • 
          
        • The pump is a 3D visualisation of the controller output, not an actuator command.
